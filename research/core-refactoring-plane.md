# Рефакторинг ядра приложения

## Основная цель

Упростить приложение. Сократить количество задействованных сервисов. Реорганизовать структуру и повысить производительность.

## Задачи

База данных:

- отказаться от векторной базы данных, так-как в данном приложении не осуществляется поиск в векторном пространстве
- реализовать простуую in-memory базу данных для хранения системных промптов и текущих метаданных игры
- нициализировать базу данных системными промптами при старте из yaml-конфига
- все текстовые данные, необходимые для работы llm хранить в общем yaml-конфиге
- в качестве in-memory бд выбрать sqlite
- использовать асинхронный корннектор к sqlite из python-кода

Сервисы агентов:

- реализовать единый сервис ai-игрока, в котором будет заключена вся логика ai-агентов
- все необходимые данные для реализации логики ai-игрока для каждого конкретного игровой сущности новый сервис будет получать из базы данных
- все необходимые данные о текущей игровой ситуации с точки зрения каждой игровой сущности будут храниться в базе данных
- для этого необходимо реализовать идентификаторы игровых сущностей, по которым будет извлекаться информация из базы данных
- для обеспечения производительности сервис будет асинхронным
- таким образом мы переходим от архитектуры "много сервисов реализующих разные игровые сущности" к архитектурые "единый сервис, реализующий запросы к разным игровым сущностям"

Оркестратор:

- задача оркестратора прежняя - управлять игровым процессом
- он отправляет/получает запросы по апи единого сервиса ai-игрока, идентифицируя каждую игровую сущность по ее id
- теперь оркестратор не отключает контейнеры агентов, когда они выбывают из игры, а направляет запрос на пометку как выбывшей игровой суцщности из бд через единый сервис ai-игрока

LLM:

- для повышения производительности необходимо выяснить доступные системные ресурсы хост-машины
- если ресурсы позволяют, модель можно загрузить на gpu
- если gpu недоступна или не соответствует требованиям модели, необходимо использовать cpu
- необходимо расчитать сколько моделей может быть запущено одновременно на предоставленных gpu/cpu
- если памяти/ядер достаточно, необходимо запустить несколько моеделей для обеспечения высокой степени парллелизма
- если запущено несколько моделей, зопросы к моделям необходимо распределять между ними
